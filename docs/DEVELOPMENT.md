# Development Platform

The development subsystem makes engineering tools first-class platform capabilities.

## Current Capability Areas

- `development/nvim`: editor capability
- `development/terminal`: terminal capability
- `development/shell`: shell capability
- `development/git`: Git workflow
- `development/tmux`: terminal multiplexing
- `development/languages`: language runtimes
- `development/toolchains`: compilers and build systems
- `development/containers`: Docker, Podman, Kubernetes
- `development/debugging`: debuggers and tracing
- `development/profiling`: performance tools
- `development/projects`: project templates and launchers
- `development/ai`: AI development workflows
- `development/ml`: machine learning workflows
- `development/security`: security engineering workflows

## Integration Rule

The desktop should reduce friction for development, but development state should not be hidden inside Hyprland config. Keep editor, shell, Git, containers, and project automation in this subsystem.
